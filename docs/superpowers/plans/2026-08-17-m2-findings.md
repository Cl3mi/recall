## The finding 2 decision — Option B, preserve ticket shares

Recorded 2026-08-17. Computed from `local/artifacts/profile.json`; no generation involved.

The real corpus has four groups ≥50, one dominant and three small (together roughly a seventh of tickets). At the fixture's scale factor (fixture size over corpus size, about 0.1) the dominant one stays large and the other three scale to a handful of tickets each (under 20), and those are *mid-band* sizes by the profiler's `2 ≤ s ≤ 49` definition. That is the whole defect: the planner books them as large, the profiler counts them as mid, and the two bands miss in mirror image.

**Chosen:** the large band keeps its measured **ticket share**. One group carries it (about a seventh of the fixture). The three groups that scale below 50 are demoted into the mid band at their scaled sizes, inside the mid band's own ticket budget. Singletons take the remainder.

| band | real | today (seed 7) | Option B |
|---|---:|---:|---:|
| singletons | about three quarters | matches | matches the real share |
| mid 2–49 | about a tenth | about 1.7 points too high | matches the real share |
| large ≥50 | about a seventh | about 1.7 points too low | matches the real share |
| groups ≥50 | 4 | 1 | 1 |
| largest cluster | a bit under a seventh | a bit under a seventh | about a seventh |

Accepted costs, stated so they are not rediscovered as bugs: the fixture has **one** cluster ≥50 where the corpus has four, and its largest cluster is slightly larger than the real largest because it absorbs the other three. The rejected alternatives were a dominant group plus three at exactly 50 (four large groups, bands several points out, acceptance criterion would have to be rewritten) and a shrunken dominant group plus three at 50 (four large groups and exact bands, but the dominant cluster flattened to a few percent).

```python
from __future__ import annotations

import hashlib
import json
import pathlib
import random
import re
from collections.abc import Callable
from typing import Protocol


class Client(Protocol):
    identity: str

    def __call__(self, prompt: str) -> str: ...


def _slug(identity: str) -> str:
    """A directory name a human can read, so a cache directory says which client filled it."""
    return re.sub(r"[^A-Za-z0-9._-]+", "-", identity).strip("-") or "client"


class Cached:
    """Wrap a client with a content-addressed disk cache, namespaced by WHO answered.

    Keying on the prompt alone made --fake a lie. Prompts are fully determined by
    profile, rows and seed and carry no trace of the client, and the cache is consulted
    before the inner client, so a stub run poisoned every entry and a later model run
    returned byte-identical stub German without ever contacting the H100 - verified
    against a dead port, exit 0, no warning, no provenance marker.

    The identity goes into the key AND into the entry: the key keeps the two runs apart,
    and the recorded identity means a hand-moved file cannot be served to the wrong
    client either.
    """

    def __init__(
        self, inner: Callable[[str], str], cache_dir: pathlib.Path, identity: str
    ) -> None:
        if not identity:
            raise ValueError(
                "a cache needs the identity of the client that fills it; without one, "
                "a --fake run answers for the model"
            )
        self._inner = inner
        self._identity = identity
        self._dir = pathlib.Path(cache_dir) / _slug(identity)
        self._dir.mkdir(parents=True, exist_ok=True)

    def __call__(self, prompt: str) -> str:
        key = hashlib.sha256(f"{self._identity}\0{prompt}".encode()).hexdigest()[:32]
        path = self._dir / f"{key}.json"
        if path.exists():
            entry = json.loads(path.read_text(encoding="utf-8"))
            if entry.get("identity") == self._identity:
                return entry["response"]
        answer = self._inner(prompt)
        path.write_text(
            json.dumps({"identity": self._identity, "response": answer}, ensure_ascii=False),
            encoding="utf-8",
        )
        return answer
```

```python
# At or above this many members, a group is a LARGE group - both here and in the
# profiler's banding, which is what the acceptance test compares against.
LARGE_GROUP = 50

# Below this, a scaled large group has vanished outright rather than been demoted: not
# one ticket of it survives anywhere. That is the one case the row-count guard refuses.
# An earlier version floored undersized groups up to a minimum of 2 instead of refusing,
# which manufactured the very minimum it was supposed to detect.
MIN_LARGE_GROUP = 1


def group_sizes(profile: dict, rows: int, seed: int) -> list[int]:
    """One entry per near-duplicate group; the list sums to `rows`.

    The large band keeps its measured TICKET SHARE (the user's decision, 2026-08-17).
    At 1,500 rows the dominant real group stays above 50 but the three smaller large
    groups scale to mid-band sizes by the profiler's 2-49 definition - so a fixture
    cannot have four groups of 50+, correct band shares and correct within-band
    proportions at once. The groups that scale below 50 are demoted into the mid band
    at their scaled size, and the surviving large group absorbs the band's remaining
    tickets so the band's share is exact against the real share.

    Mid groups are sampled at their real, unscaled size - a size-14 group in the fixture
    is a genuine size-14 group from the corpus - until the mid budget is spent, and
    singletons take whatever remains so the total is exact however the rest rounds.
    """
    rng = random.Random(seed)
    real_rows = profile["source"]["row_count"]
    dist = {int(size): n for size, n in profile["clusters"]["size_distribution"].items()}
    scale = rows / real_rows

    large = sorted(
        (size for size, n in dist.items() if size >= LARGE_GROUP for _ in range(n)),
        reverse=True,
    )
    scaled = [round(size * scale) for size in large]
    if scaled and min(scaled) < MIN_LARGE_GROUP:
        smallest_real, smallest_scaled = next(
            (real, small)
            for real, small in zip(large, scaled, strict=True)
            if small == min(scaled)
        )
        raise ValueError(
            f"rows={rows} is too small to hold the scaled large groups: a real group "
            f"of {smallest_real} tickets scales to {smallest_scaled}, under the "
            f"minimum of {MIN_LARGE_GROUP}, so it would vanish from the fixture "
            f"and its tickets be silently redistributed"
        )

    budget = round(sum(size * n for size, n in dist.items() if size >= LARGE_GROUP) * scale)
    survivors = [size for size in scaled if size >= LARGE_GROUP]
    demoted = [size for size in scaled if size < LARGE_GROUP]
    if survivors:
        survivors[0] += budget - sum(survivors)
    elif budget:
        survivors = [budget]
    sizes = list(survivors)

    # Demoted groups are mid groups now, so they are paid for out of the mid budget
    # rather than added on top of it. Adding them on top is where the old planner's
    # mid drift (too high) and large drift (too low) came from, in mirror image.
    mid_budget = round(sum(s * n for s, n in dist.items() if 2 <= s < LARGE_GROUP) * scale)
    spent = 0
    placed = []
    for size in demoted:
        if size >= 2 and spent + size <= mid_budget:
            placed.append(size)
            spent += size
    sizes.extend(placed)

    # An unscaled mid group must not outrank a demoted one: a real 58-ticket group
    # scales to a handful here, and a sampled 14 above it would put a former large structure
    # below a mid one. Capping the pool at the smallest demoted size keeps the rank
    # order the corpus has, without touching the budget, which is unrelated to rank.
    mid_cap = min(placed) if placed else LARGE_GROUP - 1
    pool = [s for s, n in dist.items() if 2 <= s <= mid_cap for _ in range(n)]
    rng.shuffle(pool)
    for size in pool:
        if spent + size <= mid_budget:
            sizes.append(size)
            spent += size

    singletons = rows - sum(sizes)
    if singletons < 0:
        raise ValueError(
            f"rows={rows} is too small to hold the scaled large groups "
            f"({sum(sizes)} tickets); the fixture would lose its structure"
        )
    sizes.extend([1] * singletons)
    return sizes
```

### Task 3: Parse what the model actually emits, and say what was padded

```python
# The model decorates the format it was given: '**TITEL:**', '1. TITEL:', '- TITEL:'.
# An unrecognised prefix used to produce a ticket with an EMPTY title, which flows into
# the fixture instead of registering as a shortfall the retry path can still fix.
_DECORATION = re.compile(r"^[\s>#*\-–—]*(?:\d+[.)])?\s*")
_FIELD = re.compile(r"^(TITEL|BEFUND|LOESUNG)\**\s*:\s*(.*)$", re.IGNORECASE)
_KEYS = {"TITEL": "title", "BEFUND": "description", "LOESUNG": "solution"}


def _parse(text: str, group: int) -> list[Ticket]:
    """The records the model actually emitted, not the ones the prompt asked for.

    A record is flushed on the separator OR on the next TITEL, because two well-formed
    records run together without a '---' used to parse as one - the earlier overwritten
    in place. A record without a title is not a ticket: emitting it with an empty title
    hid a shortfall that the retry path exists to fix.
    """
    tickets: list[Ticket] = []
    current: dict[str, str] = {}

    def flush() -> None:
        nonlocal current
        if current.get("title"):
            tickets.append(
                Ticket(
                    group,
                    current["title"],
                    current.get("description", ""),
                    current.get("solution", ""),
                )
            )
        current = {}

    for raw in text.splitlines():
        stripped = raw.strip()
        if stripped.startswith("---"):
            flush()
            continue
        match = _FIELD.match(_DECORATION.sub("", stripped))
        if not match:
            continue
        field = _KEYS[match.group(1).upper()]
        if field == "title" and current.get("title"):
            flush()  # a new record began without a separator
        current[field] = match.group(2).strip().strip("*").strip()

    flush()
    return tickets
```

```python
def tickets(
    group_sizes: list[int], client: Client, stats: dict[str, int] | None = None
) -> list[Ticket]:
    """One ticket per group member.

    Multi-member groups get one prompt each, asking for that many different approaches to
    a single fault. Singletons are batched, because asking once per singleton would send
    the same prompt over a thousand times.

    `stats` collects what had to be padded. Padding keeps a run from stalling, but it
    emits byte-identical duplicates with no solution inside a group meant to hold
    different approaches - a degradation the caller must be told about rather than
    discover in the profile afterwards.
    """
    out: list[Ticket] = []
    padded = 0
    groups_short = 0

    for index, size in enumerate(group_sizes):
        if size < 2:
            continue
        theme = THEMES[index % len(THEMES)]
        produced = _parse(client(_prompt(theme, size, index)), index)
        attempt = 0
        while len(produced) < size and attempt < 2:
            attempt += 1
            shortfall = size - len(produced)
            produced.extend(
                _parse(client(_prompt(theme, shortfall, index * 1000 + attempt)), index)
            )
        if len(produced) < size:  # the model kept coming up short; do not stall the run
            groups_short += 1
            padded += size - len(produced)
            produced.extend([Ticket(index, theme, theme, "")] * (size - len(produced)))
        out.extend(produced[:size])

    singletons = [i for i, size in enumerate(group_sizes) if size < 2]
    for series, start in enumerate(range(0, len(singletons), SINGLETON_BATCH)):
        batch = singletons[start : start + SINGLETON_BATCH]
        produced = _parse(client(_prompt_distinct(len(batch), series)), -1)
        if len(produced) < len(batch):
            groups_short += 1
            padded += len(batch) - len(produced)
        for offset, group in enumerate(batch):
            if offset < len(produced):
                item = produced[offset]
                out.append(Ticket(group, item.title, item.description, item.solution))
            else:
                out.append(Ticket(group, f"Stoerung {group}", "", ""))

    if stats is not None:
        stats["padded"] = padded
        stats["groups_short"] = groups_short
    return out
```

```python
def _allocate(mix: list[tuple[str, float]], count: int) -> list[str]:
    """Largest-remainder allocation of `count` values over the measured shape mix.

    Each shape gets floor(weight * count), and the leftover goes to the largest
    fractional parts, so every shape lands within one row of its measured proportion on
    every seed. Sampling per row instead reproduces the mix only in expectation.
    """
    exact = [weight * count for _, weight in mix]
    counts = [int(value) for value in exact]
    leftover = count - sum(counts)
    order = sorted(range(len(mix)), key=lambda i: exact[i] - counts[i], reverse=True)
    for index in order[:leftover]:
        counts[index] += 1
    return [shape for (shape, _), n in zip(mix, counts, strict=True) for _ in range(n)]
```

```python
def months_for_rows(fixture_plan, rows: int, rng: random.Random) -> list[str]:
    """One month per ticket, in the real corpus's monthly volume.

    The old code sorted fill_by_year's keys - four-character YEARS - called them months,
    cycled them round-robin and drew the calendar month at random, so ticket volume per
    year was wrong and the per-year rates were never read at all.

    The months are shuffled because group members are contiguous in the ticket list: an
    ordered assignment would drop the whole large cluster into one month and make
    its fill rate the fill rate of a single year.
    """
    weights = fixture_plan.month_weights or {
        f"{year}-{month:02d}": 1
        for year in (sorted(fixture_plan.fill_by_year) or ["2024"])
        for month in range(1, 13)
    }
    months = sorted(weights)
    total = sum(weights.values()) or 1
    exact = [rows * weights[month] / total for month in months]
    counts = [int(value) for value in exact]
    order = sorted(range(len(months)), key=lambda i: exact[i] - counts[i], reverse=True)
    for index in order[: rows - sum(counts)]:
        counts[index] += 1
    out = [month for month, n in zip(months, counts, strict=True) for _ in range(n)]
    rng.shuffle(out)
    return out


def fill_flags(
    months: list[str], fixture_plan, column: str, rng: random.Random
) -> list[bool]:
    """Which rows carry `column`, at exactly its measured share of each YEAR's rows.

    Exactly, not per-row coin flips: the same lesson customData field shares already
    learned, and at 7 rows for 2020 a flip is not a rate at all.
    """
    flags = [True] * len(months)
    by_year: dict[str, list[int]] = defaultdict(list)
    for index, month in enumerate(months):
        by_year[month[:4]].append(index)
    for year, indices in by_year.items():
        rate = fixture_plan.fill_by_year.get(year, {}).get(column)
        if rate is None:
            continue
        keep = set(rng.sample(indices, round(rate * len(indices))))
        for index in indices:
            flags[index] = index in keep
    return flags
```
