## What's done
M4 asked whether a cross-encoder over the fused top 100 separates the near-twin recipes. On the
stand-in corpus **it does not**: the best small-twin lift in any cell is +0.021 averaged over the
three query modes (bge, problem+solution) against a bar of +0.15 in every mode, and macro
recall@10 drops in at least one mode in every cell. The models work (R008 goes 0.80 -> 1.00 under
every cell, R005-R007 stay at 1.00); the twins are what does not move. Full tables are in the
plan's "Results, Phase C".

What the code is now: `RERANKERS = {"bge": BgeReranker}`, `DOC_TEXTS = ("problem_solution",)`,
`search(..., reranker, depth, doc_text)` reranks the fused top `depth` and returns the top k.
`Settings.rerank_model`, `rerank_depth`, `rerank_text` stay `None` (opt-in). The Qwen adapter and
the `problem`-only text are deleted (the losing cells' numbers stay in the plan; the code is in
git history before 23011a1).
